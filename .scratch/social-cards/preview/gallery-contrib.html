Ticket 05 — Plain, no disc, light: one layout at five text sizes

The 560px column is the constraint, not Slack’s 1068px. Every line of type on this layout lives in that column. Measured by rendering and ink-counting (probe/ticket05/plain-ramp.ts): the name fits on one line only up to 36px (556px of 560 — 4px of margin), the count only up to 30px, and the mark has no ceiling at all.
So the current card puts its name at 10.8px and its count at 7.8px on a 360px Slack card. The shelf layout measured 20.4px for the same name — that 1.9× gap is the whole difference between the two layouts, and it is why this card reads as small while looking correct at full size.
Wrapping buys the size back, and it is only the type. A name that wraps takes 56px in the same 560px column against 36px on one line, because above 36px the limit is the break point rather than the total. At 60px it takes three lines, so 56 is the ceiling. The count takes two lines by construction from 38px up. Nothing is re-laid-out: same column, same 3×2 grid of 152px tiles, same margins — except Wide, which drops the grid to 2×2 to buy the name one line and is the price of that, shown.
Two break bugs, both found by rendering rather than reasoning. CSS breaks CJK between any two characters, so at 56px Daehyeon Mun (문대현) came out as (문대 / 현) — and lib/contributor-match.ts:27-31 exists because every slugifier here has already destroyed that name. word-break: keep-all fixes it and Satori honours it. But Satori’s break point is not monotonic in the size: 44px breaks Enzo Manuel Mangano ( / Reactiive) cleanly and 52px orphans the parenthesis again. Binding the parenthetical to its word with a non-breaking space removes the decision. Current keeps the shipped behaviour, defects included, because a control with the bugs fixed is not a control.
