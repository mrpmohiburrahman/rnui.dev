Problem

A Category converts to three different strings — display name, legacy URL slug, asset directory slug — and no module owns any of them. Adding one means six hand-edits.

Solution

One module holding one row per Category. middleware.ts, the Zod schema, the meta keywords, and the ingest script all read it.

Wins

  • locality: new Category = one row
  • leverage: one table, 6 call sites
  • slug drift becomes a type error

4 · An Asset path module

Before — the scheme restated nine times

demo/<slug>/x.mp4 · thumbnails/<slug>/x.avif
codex-ingest.ts:120 builds import-items.js:141 builds ✗ generateThumbnails.ts:81 .jpg ✗ asset-paths.ts:15 prefixes publish-assets.ts:30 ext→mime publish-assets.ts:87 public/ check-video-codecs.sh:108 ext set check-video-codecs.sh:83 public/ codex-ingest.ts:137 public/ codex-review-pr.ts:31 as English data-integrity.test.ts:82 the only spec lib/cdn.ts:41 leading /
lib/cdn.ts — knows how to prepend a base URL. Knows nothing about prefixes, slugs, or extensions.

After — one module, three adapters

interface

demoPath(category, slug) · posterPath(category, slug)
parse(path): {kind, category, slug} | null
stagingFile(path) · publishedUrl(path) · contentType(path)

implementation

prefixes · Category slug (from module 2) · extension per kind · public/ staging root · CDN base · leading-slash normalisation
browser
Published Asset
publish
Staging copy
ingest
new path

Three adapters over one interface — the seam is real, not hypothetical.

Problem

The Asset path scheme is stated in nine places and specified in none — its only formal definition is a regex inside a test.

Solution

One module that builds, parses, and locates an Asset path. lib/cdn.ts becomes its Published-Asset adapter.

Wins

  • locality: scheme lives in one module
  • interface becomes the test surface
  • immutability enforceable, not conventional

The documented Poster workflow produces a Poster that fails pnpm test.

scripts/generateThumbnails.ts:81-84 writes .jpg. The catalogue and tests/data-integrity.test.ts:83 require .avif. The .jpg → .avif step lives in convert-to-avif.js, which is referenced by nothing and slated for deletion in candidate 1. Meanwhile publish-assets.ts:45-47 and check-video-codecs.sh:41-46 each carry a comment saying the other must match — and nothing asserts it. That agreement guards an upload that is immutable for a year.

Consistent with ADR-0003 (Asset paths are immutable), not against it. A path module makes the invariant something a type and a parser enforce, rather than something nine call sites remember. ADR-0001 (object storage) is untouched — the module's Published-Asset adapter is lib/cdn.ts as it stands.

Top recommendation

1 · Delete the phantom half of the tree

It is the cleanest answer the deletion test ever gives: roughly 1,500 lines, including the two largest modules in the repo, have zero importers — and resource-card-grid-virtualized.tsx has had zero for its entire git history while exporting the same symbol name as the grid that ships. Nothing here needs designing.

Do it first because it changes the answers to the other eight. Two live comments and one e2e test currently reason about a virtualised grid that does not exist; candidate 4's Poster bug is partly held open by a dead convert-to-avif.js; a pre-commit hook checks out origin/main on every commit to run a script that diffs its own empty output. Until the unreachable code is gone, every survey of "what shape should this be" is surveying a phantom.

Then, in order

  1. 2 — Category module. The deepest of the deepenings, and the one already shipping a wrong Asset path.
  2. 4 — Asset path module. Builds on 2; guards the one operation in this repo that cannot be undone.
  3. 5 — Collapse the page clients. Fixes the double view-count as a side effect of having one module.
