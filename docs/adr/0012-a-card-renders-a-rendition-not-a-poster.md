# A card renders a Rendition, never a Poster

An Open Graph card is rendered by Satori, and Satori's image allowlist is `[png, apng, jpeg, gif, svg+xml]` — it detects AVIF by its magic bytes and then declines it. Every Poster in this catalogue is AVIF (`lib/asset-path.ts`), so a card that composites a Poster renders **completely blank**: one colour, the canvas, no 500 and no thrown error, because the rejection is swallowed. A shared link would show a card with the Recording missing and nothing would say so.

The catalogue is not changing format to suit a card renderer. AVIF is right for a Poster — it is 15 KB where a JPEG rendition is 25 KB at card size, and it is what 297 assets across 4.5 MB are already stored as. So the conversion happens on the way out instead: **a Poster's bytes are encoded a second time, at card size, and published beside it.** That second encoding is a **Rendition** (`CONTEXT.md`). It is derived, never authored; it is not an Asset the catalogue names; and no page ever fetches one.

## Considered options

- **Transcode per request with `sharp`.** Measured at **17.9 ms** per Poster, and the realistic figure is worse: the image LRU is 100 entries keyed by URL against 297 Recordings, so a card re-fetches its rendition on any cold isolate. It also carries a runtime cost nobody had named — `sharp` is a native addon and Vercel's Edge Runtime forbids native Node APIs, while `app/opengraph-image.tsx` runs `runtime = "edge"`, so this would force `nodejs`. Rejected: recurring cost, for a conversion that does not change once the catalogue stops changing.
- **Convert at the edge with Cloudflare `/cdn-cgi/image`.** The appealing version of this idea is that it costs nothing per request, because Cloudflare does it. Measured against the live CDN: every variant returns `403 ERROR 9401: Transformation origin is not in allowed origins list`. It is a zone setting that is currently closed, not a service to evaluate, so it would add a Cloudflare configuration dependency to a decision that can be made once and locally. Rejected — but not forever; see Consequences.
- **Publish no image on any card.** The cheapest answer, and it would have worked: the AVIF problem, the runtime change and the storage cost all disappear together. Rejected because it gives up the one thing a share of this site can show. The site's proposition is moving pictures, and a link preview is the only place a stranger sees one — the Contributor and Category cards are already text-only, and they can afford it, because a name and a count *are* the content. A Recording is different: it is the only card in the set with something to show that is not its own metadata.
- **Change the Poster format to JPEG.** Rejected on ADR-0003's terms: a Poster is one specific frame at one specific path, and `.avif` is enforced independently by `lib/asset-path.ts` and by `tests/data-integrity.test.ts` (ADR-0005 keeps those two restatements separate on purpose). Trading a format decision for a renderer preference inverts the dependency.

## Consequences

- **A Rendition is 1200×630 and nothing else.** Measured across all 303 Posters: **7.3 MB total, 25 KB average**. Full-size 1108×2410 renditions would be 24.1 MB, and a card never composites beyond 1200×630, so the full-size variant is the wrong artefact to publish.
- **The catalogue does not know Renditions exist.** `allAssetPaths` is `demoPath` + `posterPath` (`data/catalogue.ts`). A Rendition is deliberately absent from it — a tool that walks `allAssetPaths` should not acquire a second kind of thing to handle — so publication and the Poster generator need their own rule for where a Rendition goes, derived the same way `posterPathFor` derives a Poster.
- **Renditions are immutable, exactly like every other Published Asset** (`public, max-age=31536000, immutable`). They are written once, so ADR-0003's reasoning holds without exception, and a re-recorded Demo leaves its superseded Poster and superseded Rendition on the store together as orphans.
- **A card must treat a missing image as a designed state, not a hole.** The blank-card failure is invisible, and it is not only AVIF: an R2 404, a deleted Recording or a cold cache all produce the same one-colour card. The fallback is the grid's own — a hue-tinted panel with a device outline, using the Recording's measured `hue` where it has one (**215 of 297** do, via `lib/poster-hue.ts`) and the site's `--tile-hue` green where it does not. That is not a new visual idea; it is what an unmeasured Recording already shows in the grid today.
- **A card that composites a rendition is `runtime = "nodejs"`.** Renditions remove the transcoding cost but not the in-render network fetch, and the edge runtime's constraints make that a choice to be made rather than inherited. Cards that composite no image may stay `edge`.
- **No platform ever sees the AVIF.** A card's `contentType` is PNG, so Slack, X and Messages decode our PNG, not the Poster — which is why no platform's AVIF support was measured. Slack proxies images through `Slack-ImgProxy` and AVIF appears in no published format list, but that fact is about a path this design does not take.
- **Cloudflare's edge transform stays closed.** If the catalogue ever grows past the point where a one-off 4-second conversion is acceptable per addition — thousands of new Posters a release — option 2 above becomes the cheaper answer and this ADR should be revisited rather than worked around.
